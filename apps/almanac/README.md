# almanac

Личный серверный источник истины: факты, страницы, задачи и события. Модели
пишут и читают через MCP, владельцу остаются Telegram и календарь.

Замысел и границы POC — в [SPEC.md](./SPEC.md).

## Как устроено

- **Факты** — сырьё, только дописываются.
- **Страницы** и **элементы** (задачи, события) — проекции, каждая называет
  факты, из которых собрана.
- Агент видит всё как файловое дерево: `ls`, `grep`, `read`, `edit`.
- Напоминания шлёт бот Telegram; календарь телефона подписывается на ICS-ленту.

## Запуск у себя

```bash
cd apps/almanac
uv run pytest -q
uv run python -m almanac.auth.owner          # спросит пароль, напечатает хэш для OWNER_PASSWORD_HASH
uv run alembic upgrade head                  # создаёт и обновляет схему базы
uv run uvicorn almanac.app:create_app --factory --port 8000
```

Приложение само таблиц не создаёт: схему ведёт Alembic. В образе перед каждым
стартом идёт `python -m almanac.migrate`: проверка тома, копия базы и
`alembic upgrade head`.

## Окружение

| Переменная | Зачем |
| :-- | :-- |
| `BASE_URL` | внешний адрес сервера; от него строятся адреса OAuth. Только `https://…`; `http://` годится лишь для самой машины (`localhost`, `127.0.0.1`, `::1`), иначе приложение не стартует |
| `DATABASE_URL` | база; в образе `/data/almanac.db`, том `/data` должен принадлежать пользователю с uid 1000 |
| `OWNER_PASSWORD_HASH` | хэш пароля владельца вида `scrypt:N:r:p:соль:хэш`; его печатает `uv run python -m almanac.auth.owner` |
| `OWNER_TZ`, `DAY_START` | часовой пояс владельца (например, `Europe/Berlin`) и начало его дня (`HH:MM`) |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_CHAT_ID` | бот и цикл напоминаний; запускаются, только когда заданы оба, иначе срабатывания копятся в базе и не уходят |
| `ICS_TOKEN` | секрет в адресе календарной ленты; без него ленты нет |
| `MCP_CODE_MODE` | `0` — показать инструменты напрямую, без Code Mode |
| `BACKUP_DIR` | каталог суточных копий базы; в образе `/data/backups`, без переменной копий нет |
| `DATA_MOUNT` | каталог, который обязан быть смонтированным томом; в образе `/data`. Не смонтирован — `python -m almanac.migrate` завершается с кодом 1, сервер не стартует |
| `SCHEMA_DIR` | свои `guide.md` и `types.toml` |

## Доступ

- **Владелец в браузере.** Страница `/login` просит пароль; после входа сессия
  живёт 30 дней.
- **Модели.** Дверь MCP — `<BASE_URL>/mcp/`, со слэшем на конце. Клиент
  проходит OAuth: страница согласия `/oauth/consent` требует входа владельца и
  показывает, куда уйдёт код доступа.
- **Календарь.** Лента лежит по адресу `<BASE_URL>/calendar/<ICS_TOKEN>.ics`;
  кто знает адрес, тот читает ленту, поэтому секрет не публикуют.
- **Снять всё разом.** `python -m almanac.auth.revoke` (у себя — с `uv run`
  впереди, на сервере `uv` нет) удаляет всех клиентов OAuth, их токены и коды, а
  заодно сессии владельца. После неё каждый клиент проходит согласие заново, а
  браузер входит по паролю. Команда запускается там, где лежит база; в сети
  такой кнопки нет.

## Данные и выкладка

- **База — один файл на постоянном томе**, смонтированном в `/data`. Том
  обязателен и должен быть доступен на запись пользователю с uid 1000. Без
  смонтированного тома контейнер отказывается стартовать
  (`DATA_MOUNT=/data is not a mounted volume`): так забытый том не превращается
  молча в пустую базу при каждой выкладке.
- **Копии лежат в `/data/backups`**: по одной на сутки UTC за последние
  четырнадцать (`almanac-ГГГГММДД.db`) и `pre-<ревизия>.db` перед каждой
  миграцией. Они защищают от порчи и от ошибочной записи, но **не от потери
  тома**: они лежат на том же диске. Копия вне сервера пока не настроена, и её
  нужно настроить до того, как в базу попадут настоящие записи.
- **Восстановление.** Остановить контейнер, удалить `almanac.db-wal` и
  `almanac.db-shm` рядом с базой, скопировать выбранную копию поверх
  `almanac.db`, запустить контейнер.
- **Один контейнер за раз.** Старый должен остановиться раньше, чем стартует
  новый: никаких постепенных обновлений и перекатов по проверке здоровья.
  Иначе напоминания придут дважды, а миграция пойдёт под работающим
  приложением.
- **Команды на сервере** идут без `uv`: `python -m almanac.auth.revoke`,
  `python -m almanac.auth.owner`.
- **Локальная база, созданная до появления миграций**, обновиться не может:
  удалите её и запустите `python -m almanac.migrate` (или
  `alembic upgrade head`).

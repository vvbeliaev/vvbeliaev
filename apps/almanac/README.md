# almanac

Личный серверный источник истины: факты, страницы, задачи и события. Модели
пишут и читают через MCP, владельцу остаются Telegram и календарь.

Замысел и границы POC — в [SPEC.md](./SPEC.md).

## Как устроено

- **Факты** — сырьё, только дописываются.
- **Страницы** и **элементы** (задачи, события) — проекции, каждая называет
  факты, из которых собрана.
- Агент видит всё как файловое дерево: `ls`, `grep`, `read`, `edit`, `move`.
- Напоминания шлёт бот Telegram; календарь телефона подписывается на ICS-ленту.

## Запуск у себя

Нужны Docker, `uv` и `make`.

```bash
cd apps/almanac
make up        # база в Docker, миграции, сервер на http://127.0.0.1:8910
make status    # идёт ли сервер, с какого коммита, ревизия базы
make logs      # хвост журнала .run/server.log
make down      # останавливает сервер; база остаётся
make dump      # дамп базы в ~/almanac-backups
make test      # ruff и pytest; тесты поднимают свой Postgres и рабочую базу не трогают
```

- **База** — Postgres 18 в контейнере (`compose.yml`). Порт открыт только на
  `127.0.0.1:5434`, вход по паролю. Данные лежат в томе Docker
  `almanac_almanac-pg` и переживают `make down` и перезапуск Docker.
- **Настройки.** Первый `make up` создаёт `.env`: `OWNER_TZ` — пояс машины,
  `POSTGRES_PASSWORD` и `DATABASE_URL` — пароль базы, случайный и нигде не
  печатаемый. Файл читают сервер, дверь MCP и compose. Остальное (бот Telegram,
  `ICS_TOKEN`, пароль владельца) дописывает владелец; таблица ниже. Потерян
  `.env` — потерян и пароль: базу тогда возвращают из дампа в новый том.
- **Миграции.** `make up` и `make migrate` перед обновлением схемы снимают дамп
  в `~/almanac-backups`. Вернуть базу из дампа: `make down`, затем
  `docker compose exec -T db pg_restore -U almanac -d almanac --clean --if-exists < файл.dump`.
- **Сон.** Пока сервер идёт, мак не засыпает от простоя (`caffeinate -i`):
  спящая машина напоминаний не шлёт. Закрытая крышка усыпляет всё равно.

### Claude Code на этой машине

Локальная дверь MCP — тот же сервер по stdio: Code Mode, те же инструменты и
отказы, но без OAuth и пароля. Процесс запускает сам клиент; кто может его
запустить, тот и так читает базу. В журнале такие записи подписаны клиентом
`local`.

```bash
claude mcp add almanac --scope user -- uv run --directory /полный/путь/к/apps/almanac python -m almanac.local
```

Двери нужна только база: сервер может идти рядом, может стоять. Бот и
напоминания она не запускает — это дело сервера (`make up`).

### Сайт

Только чтение: неделя и сегодняшний день, входящие, страницы, дела, журнал
фактов и поиск. `make up` собирает его в первый раз (нужен `pnpm`) и отдаёт с
корня — `http://127.0.0.1:8910/`. После правок в `web/` — `make web`; разработка
с горячей перезагрузкой — `make web-dev`.

Поднятый через `make` сервер слушает только `127.0.0.1`, и сайт читает без
входа (`LOCAL_SITE=1`): только `GET`, только соединения с самой машины, не через
прокси и только с адресом сервера в `Host`. Запись и согласие OAuth входа
требуют по-прежнему.

Это защищает от чужого сайта, открытого в браузере на этой машине, но не от
чужой программы на ней: любой местный процесс и любой контейнер Docker тоже
приходит «с самой машины» и прочтёт записи через сайт. Не подходит —
`LOCAL_SITE=0` в `.env` и `OWNER_PASSWORD_HASH`: сайт станет спрашивать пароль.

`web/` — свой корень pnpm со своим lockfile, вне общего workspace репозитория.
В образ сайт едет собранным: стадия `web` в `Dockerfile` гоняет его проверки и
тесты и кладёт `dist` рядом с сервером. На публичном адресе сайт требует входа.

Сервер без `make` — те же шаги руками: `uv run alembic upgrade head`, затем
`uv run uvicorn almanac.app:create_app --factory --port 8910`. Приложение само
таблиц не создаёт: схему ведёт Alembic. В образе перед каждым стартом идёт
`alembic upgrade head`; не накатилась — контейнер не стартует.

## Окружение

| Переменная | Зачем |
| :-- | :-- |
| `BASE_URL` | внешний адрес сервера; от него строятся адреса OAuth. Только `https://…`; `http://` годится лишь для самой машины (`localhost`, `127.0.0.1`, `::1`), иначе приложение не стартует |
| `DATABASE_URL` | Postgres: `postgresql+asyncpg://пользователь:пароль@хост:порт/база`. Другой драйвер приложение не принимает. Локально адрес с паролем пишет в `.env` первый `make up`; в образе адреса нет, он приходит окружением контейнера |
| `OWNER_PASSWORD_HASH` | хэш пароля владельца вида `scrypt:N:r:p:соль:хэш`; его печатает `uv run python -m almanac.auth.owner` |
| `OWNER_TZ`, `DAY_START` | часовой пояс владельца (например, `Europe/Berlin`) и начало его дня (`HH:MM`) |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_CHAT_ID` | бот и цикл напоминаний; запускаются, только когда заданы оба, иначе срабатывания копятся в базе и не уходят |
| `ICS_TOKEN` | секрет в адресе календарной ленты; без него ленты нет |
| `MCP_CODE_MODE` | `0` — показать инструменты напрямую, без Code Mode |
| `LOCAL_SITE` | `1` — браузер этой же машины читает без входа; только при `BASE_URL` на саму машину, иначе приложение не стартует. `make up` включает сам |
| `SITE_DIR` | каталог собранного сайта; по умолчанию `web/dist`, нет каталога — нет сайта |
| `SCHEMA_DIR` | свои `guide.md` и `types.toml` |

## Доступ

- **Владелец в браузере.** Страница `/login` просит пароль; после входа сессия
  живёт 30 дней.
- **Модели.** Дверь MCP — `<BASE_URL>/mcp/`, со слэшем на конце. Клиент
  проходит OAuth: страница согласия `/oauth/consent` требует входа владельца и
  показывает, куда уйдёт код доступа.
- **Календарь.** Лента лежит по адресу `<BASE_URL>/calendar/<ICS_TOKEN>.ics`;
  кто знает адрес, тот читает ленту, поэтому секрет не публикуют.
- **Снять всё разом.** `python -m almanac.auth.revoke` (у себя — с `uv run`
  впереди, на сервере `uv` нет) удаляет всех клиентов OAuth, их токены и коды, а
  заодно сессии владельца. После неё каждый клиент проходит согласие заново, а
  браузер входит по паролю. Команда запускается там, откуда есть доступ к базе;
  в сети такой кнопки нет.

## Данные и выкладка

- **Данные лежат в Postgres**, контейнер приложения без состояния: ни тома, ни
  каталога с данными ему не нужно. Адрес базы приходит в `DATABASE_URL`
  окружением контейнера; в образе его нет.
- **Схема.** Перед каждым стартом идёт `alembic upgrade head`. DDL в Postgres
  транзакционный: упавшая миграция не оставляет половину схемы.
- **Копии — дампы Postgres** (`pg_dump`). Их настраивают при выкладке средствами
  базы или хостинга: приложение копий не делает, и дамп перед миграцией — тоже
  дело снаружи. Копия должна лежать вне сервера базы и быть настроена до того, как
  в базу попадут настоящие записи.
- **Восстановление.** Остановить контейнер, развернуть дамп в пустую базу
  (`pg_restore`), запустить контейнер: `alembic upgrade head` доведёт схему до
  версии образа.
- **Один контейнер за раз.** Замок записи лежит в самой базе и держит в очереди
  и несколько процессов, но бот и цикл напоминаний живут в процессе. Старый
  контейнер должен остановиться раньше, чем стартует новый: никаких постепенных
  обновлений и перекатов по проверке здоровья. Иначе напоминания придут дважды, а
  миграция пойдёт под работающим приложением.
- **Команды на сервере** идут без `uv`: `python -m almanac.auth.revoke`,
  `python -m almanac.auth.owner`.

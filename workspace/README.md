# workspace

«Кухня» — всё сырое и несборочное. Astro сюда не заглядывает; в прод напрямую
отсюда ничего не попадает. Корень репо чистый, всё черновое — здесь.

**Репозиторий публичный.** Поэтому кухня разделена на две части с жёсткой
границей:

```
workspace/
  README.md        эта карта
  assets/          бренд-ассеты для соцсетей и README (публично)
    corona-bloom-banner.svg
    social/        OG/квадрат/вертикаль/YouTube-баннер + генератор
  private/         НИКОГДА НЕ В GIT (.gitignore: workspace/private/)
    cv/            резюме: backbone → reflections → pdf/html (контакты, телефон, внутренние заметки)
    drafts/        сырые черновики статей: ideas.md + <slug>/main.md
    strategy/      стратегия бренда и дистрибуции, форматы, карта платформ
    projects/      мета-работа по проектам: <name>/ — брифы, заметки, ресёрч
    cad/           3D-модели для печати
    inbox/         «разобрать»
```

## Правило private/

- Всё, что содержит контакты, внутренние оценки, черновые мысли, чужие данные,
  описания клиентов/работодателей глубже публичного портфолио — только в
  `workspace/private/`. Сомневаешься — в `private/`.
- В публичную часть попадает только то, что готово к показу: сайт и его контент,
  дизайн-система, документация репозитория, брендовые ассеты, спеки.
- Нужен публичный артефакт из приватного (например, PDF резюме) — кладём копию в
  `apps/vvbeliaev/public/`, а не открываем папку.
- `private/` живёт только на машине владельца; бэкап — вне git (iCloud/архив).
  Не рассчитывай найти его в клоне.
- CI (`.github/workflows/guard.yml`) валит пуш, если в диффе появился секрет
  (gitleaks) или путь `workspace/private/`.

## Поток статьи (этапы)

```
1. private/drafts/ideas.md                     идея, одна строка
2. private/drafts/<slug>/main.md               русский черновик, свободная форма
3. apps/vvbeliaev/src/content/blog/note-NN-slug/ru.mdx   оформляем RU в схему, draft: true
4. apps/vvbeliaev/src/content/blog/note-NN-slug/en.mdx   перевод EN, translatedFrom: "ru"
5. снимаем draft: true                          выпуск
```

«Кухня» (шаги 1–2, приватно) → «витрина» (`src/content/blog`, шаги 3–5, публично).
Граница осознанная: **выпуск — это перенос черновика в коллекцию и оформление
по схеме, а не смена флага.** На «кухне» нет схемы и ограничений; в «витрине»
запись проходит `content.config.ts`, получает номер и рендерится.

## Конвенции витрины

- **Папка на статью:** `blog/note-NN-slug/ru.mdx` + `en.mdx`. Симметрично черновикам;
  обложка и ассеты статьи лежат в той же папке.
- **Связь RU↔EN — общий `articleNumber`.** Номер статьи и так сквозной ритуал бренда;
  он же служит ключом связи между языковыми версиями. Новых полей для линковки не нужно.
- **Маркер перевода:** в EN-версии перевода — `translatedFrom: "ru"` во frontmatter.
  В UI рендерится плашкой «Translated from Russian» со ссылкой на оригинал.
- **Slug/URL:** роуты `blog/[...slug].astro` строят путь из `post.id`, а у вложенной
  папки `id` = `note-NN-slug/ru`. Чтобы язык не задваивался в URL
  (`/blog/note-NN-slug/en`), при первом выпуске парной статьи в обоих
  `[...slug].astro` slug выводить как `post.id.replace(/\/(ru|en)$/, "")`.
  Плоские старые заметки (`note-01-...`) от этой правки не страдают.

## Что ещё предстоит (на первый перевод)

- Плашку «Translated from …» — по `DESIGN.md` (UI-компонент, обновить документ в lockstep).
- Правку slug в обоих `[...slug].astro` (см. выше).
